# Playwright e2e

- Discovery: `tests/helpers/fetchAppLinks.ts` crawls the rendered [App Builder](https://shapediver.github.io/GrasshopperExampleModels/11-AppBuilder/definitions.html) and [BETA](https://shapediver.github.io/GrasshopperExampleModels/BETA/definitions.html) pages. Do not parse `definitions.md` — those files are stubs filled from `examples.json` at docs build. Every discovered slug gets smoke + visual tests; `scenarioActions.ts` only adds interactions.
- Scenarios: `tests/config/scenarioActions.ts` — one entry per slug: `params` (e.g. `g` for settings file), `actions(page, slug)` or `namedActions[]` (one Playwright test per name). E-commerce and tools APIs have dedicated specs (`tests/specs/ecommerceApi.spec.ts`, `tests/specs/toolsApi.spec.ts`) so they do not duplicate smoke/visual of the execute-actions example. Those specs loop a named `actions[]` (one Playwright test per API method).
- Helpers: `viewportCoords` (normalised to the canvas bounding box; canvas starts at **x=300** in the default layout), `waitForModelRecomputed`, `takeSnapshot`, `getParameterElement`, `getStandardContainer` / `setViewportBelowMobileBreakpoint` / `setViewportBelowNavbarBreakpoint` / `openAppShellNavbar` / `expectAppShellNavbarCollapsed` (`tests/helpers/appBuilderContainers.ts`; AppShell `md` is 992px; collapsed navbar uses the `hidden` attribute — Playwright `toBeHidden()` is not reliable because Mantine CSS keeps a layout box). E-commerce and tools e2e both use the localhost parent on `http://127.0.0.1:3000` (`tests/fixtures/cross-window`, iframe `name="app"`). E-commerce: `openCrossWindowScenario`, parent `__connector`. Tools: `openToolsApiScenario` (`?api=tools`), Open agent stubbed to `window.parent` because deployed App Builder sends COOP `same-origin` (a popup to localhost has `window.opener === null`); parent `__toolsApi`. SDV, recompute, and notifications use `sdvTarget(page)` (the iframe). Settings `agentOverride` is a test intercept so Open agent appears; App Builder source is unchanged.
- Device: Desktop Chrome. `use.viewport` is 1280x800 but the project's `devices["Desktop Chrome"]` sets 1280×720, which is what snapshots capture. Hardware GL via `launchOptions.args` (`--use-angle=d3d11` on Windows only, `--ignore-gpu-blocklist --enable-gpu` everywhere). Mobile-fallback cases resize below `md`.
- Deterministic snapshots use a solid-color settings file via `params: {g: ...}` instead of pixel tolerances.
- New behaviours get a scenario entry; models not yet on the test server get the **entry without running it**.
- Interaction gestures assert that the object moved (`boundsChanged`). Confirm and Cancel appear after a handle moves. A selection alone leaves them hidden, so a missed drag fails the Confirm assertion. Positions come from the scene at runtime (`tests/helpers/sceneCoords.ts`: `camera.project` of node bounding boxes / parameter values), never from fixed canvas coordinates: the camera re-frames after the first customization and the geometry moves with every transform. Click a box at the projected bounding-box center (the top face center of a tilted box lies outside it). The gumball handle needs a hover update before the press. A press near a scaling handle without movement rescales. Rectangle translation grabs the base plane only away from the scaling handles, so zoom in first; older Viewers deselect the object instead.
- `automaticSceneUpdate` is alwaysActive-only (gumball, rectangle transform, drawing). A file that sets the flag without always-active must show that it is ignored. Values are **absolute placements**: a request carries the current placement of every transformed object, and Confirm without a move may resend an unchanged matrix. Customizations are counted as PUT requests to `/output`. Gumball and rectangle must **not** PUT on select (identity gizmos); after an idle PUT the gizmo is recreated on the new nodes. A second drag that starts after the idle timeout rebuilds the gizmo mid-drag. A pointer hold pauses the countdown only while pressed, so compute the screen points up front and run both drags back to back.
- `appBuilderOverride` replaces Grasshopper JSON. A custom interaction parameter must be re-declared with `settings.type`, and control refs use `sessionId: "default_appbuilder"`. A gumball override drops rectangle-only props. Accordion `overrides` deep-merge into Grasshopper `settings`; a widget presentation in the definition wins over an override that does not set it. A single always-active drawing toggle is read-only and is **not** promoted to a toolbar checkbox; assert the drawing settings menu.
- An exclusive rectangle transform hover-previews without selecting. On a thin box the projected center lies within reach of the preview rotation handle, which wins the press and rotates instead of translating. Approach from a direction that misses that handle.
- Slugs used by the interaction examples must be in `modelstorage.slugs.ts`. `pnpm run convert-slug-data` refreshes the hourly platform access token in `modelstorage.local.ts` (an expired token shows "Invalid token" / 403 on localhost) and skips slugs whose model no longer exists.

## Deploy / global setup

Global setup caches the app links (public pages plus the testing account, which needs `PLATFORM_CLIENT_ID` and the platform access key/secret from `.env.platform-access`), runs `pnpm i` (skipped with `APPBUILDER_E2E_SKIP_INSTALL=1` or in CI) and deploys the HEAD of the checkout the tests run from to `TEST_BRANCH` (default `testing/local`) via `pnpm run publish` (tsc 0, sentry-cli, AWS credentials, `.env`). On a `testing/*` branch the publish script skips its clean-tree check, so uncommitted and untracked files are deployed too. Global setup skips the deploy when the tag `AppBuilderMain@<TEST_BRANCH with / as +>` already points at `HEAD`, so a rerun after uncommitted edits tests the previous build: commit before each run. `SKIP_DEPLOY=1` skips the deploy, CI skips it unless `APPBUILDER_E2E_DEPLOY=1`, and a tag already pointing at HEAD skips it as well. A stale local `testing/local` branch **blocks** the deploy.

`APPBUILDER_BASE_URL` (e.g. `http://127.0.0.1:8080/`) runs `appbuilder.spec.ts` against that server instead of the branch deploy and skips the deploy (`resolveTestUrl` keeps only the query of the scenario URL). Use it for uncommitted work: start the worktree's dev server (`BROWSER=none pnpm exec vite --host 127.0.0.1 --port 8080 --strictPort`; port 3000 is the cross-window fixture server). Global setup still needs `.env.platform-access` (gitignored, copy it into a new worktree), and the worktree's `node_modules` must match `package.json` (an outdated viewer breaks the app at load). A checkout that links `../Viewer` (`viewer.local.ts`) serves whatever that Viewer checkout contains. To prove a test reproduces a bug, park the fix in a temporary commit, `git switch --detach origin/development` in `src/shared`, run, switch back, `git reset --soft HEAD~1`.

**Do not deploy or rerun e2e unless the user asks or `/implement` or `/spec` runs it.**
