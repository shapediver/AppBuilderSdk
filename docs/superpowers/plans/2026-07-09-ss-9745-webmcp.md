# SS-9745 WebMCP Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register four WebMCP imperative-API tools on App Builder so external AI agents can list parameters, set values, and create/import model states; reuse schemas for a future in-app agent framework.

**Architecture:** New FSD slice `src/shared/features/webmcp` in AppBuilderShared submodule. `useWebMcpTools` registers tools on `document.modelContext` (fallback `navigator.modelContext`) after session + parameters are ready. Zod `strictObject` schemas → hand-rolled `zodToJsonSchema` → `registerTool`. Set/list logic is unit-tested headless; create/import roundtrip deferred to subagent QA (schema-only in `eval:webmcp`).

**Tech Stack:** React 19, TypeScript, Zod 4, Zustand, Vite, Jest, Chrome WebMCP origin trial, ShapeDiver session API.

**Status (2026-07-16):** **SS-9745 scope complete.** 4 tools wired, **51 unit tests** (`parametersFilter` + `webmcp` + `getUiParameterRefs`) + 25 headless evals pass, weak-model QA on SS-8076/SS-8557. Post-review hardening (Task 8) + PR #334 follow-ups (Task 9) done. Canonical create-model-state Zod in `model-state`. Follow-ups deferred (see end).

## Tool contracts (current)

### `list_parameter_definitions`

- Input: `{ filter?: 'all' | 'visible', sessionId?: string }` — not `visibleOnly`
- Output: `{ parameters: [...], errors?: [{ name, message }] }` — each item has `settable: boolean`
- `filter=visible`: parameters where `!definition.hidden` (store-based, not layout)
- `filter=all`: every session param; unsupported types listed with `settable: false`

### `set_parameter_values`

- Input: `{ updates: [{ name, value, sessionId?: string }] }` — not `parameters` / `id`
- StringList: 0-based integer index only
- Output: `{ applied: string[], errors: [{ name, message }] }` — parse errors use `name: "*"`
- `sessionId` per update resolves lookup + write in same namespace

### `create_model_state`

- Success: `{ success: true, modelStateId, modelViewUrl, ... }`
- Failure: `{ success: false, error }`

### `import_model_state`

- Success: `{ success: true, appliedParameterIds, invalidParameters?: [...] }` — `appliedParameterIds` = ids that changed; `[]` if none; `invalidParameters` when partial import skipped params
- Failure: `{ success: false, message, invalidParameters?: [{ name, message }] }` on total validation fail (empty on fetch errors)
